# Task: SSE stub + discovery endpoints

## Description
Implement the SSE stream stub and the three discovery endpoints. The SSE endpoint exists and responds correctly in this phase; full reconnection logic and real event emission are deferred to Phase 4.

## Acceptance Criteria
- [ ] `GET /v1/stream/changes` — returns 200 with `Content-Type: text/event-stream`, sends a single SSE comment (`": ok

"`) as a keepalive, then holds the connection; Developer+ only; stub — no real price change events yet
- [ ] `active_sse_connections` OTel UpDownCounter gauge incremented on connect, decremented on disconnect
- [ ] `GET /openapi.json` — returns a valid OpenAPI 3.1 JSON document describing all 9 `/v1/` endpoints; no auth required
- [ ] `GET /.well-known/ai-plugin.json` — returns AI plugin manifest with `name_for_model`, `description_for_model`, `api.url` pointing to `/openapi.json`; no auth required
- [ ] `GET /llms.txt` — returns plain-text listing of all model IDs and current prices, one per line, suitable for agent context loading; no auth required; cached 10 minutes
- [ ] OpenAPI spec validates against OpenAPI 3.1 schema (use `go-openapi` or embed a static JSON file)
- [ ] All discovery endpoints return correct `Content-Type` headers
- [ ] Unit test for `/openapi.json` (valid JSON, contains all 9 paths) and `/llms.txt` (non-empty, correct format)

## Technical Details
- New files: `internal/api/handlers/sse.go`, `internal/api/handlers/discovery.go`
- OpenAPI spec can be a static embedded file (`//go:embed openapi.json`) generated once and checked in, or dynamically generated from route registration — static embed is simpler and preferred
- `active_sse_connections` gauge: use `go.opentelemetry.io/otel/metric` UpDownCounter; instrument name `llm_pricing.sse.active_connections`
- `/llms.txt` format: one line per model — `{provider}/{model_id}: input=${price_input}/1M output=${price_output}/1M`
- SSE stub does not need to implement `Last-Event-ID` reconnection logic (Phase 4 concern)
