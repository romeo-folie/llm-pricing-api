# Task: Pro endpoints + webhook asynq delivery

## Description
Implement the Pro-tier webhook management endpoints and the asynq-based webhook delivery job. Reuses the existing asynq worker scaffold from Phase 1.

## Acceptance Criteria
- [ ] `POST /v1/webhooks` — registers a webhook URL for a Pro-tier API key; validates URL format; returns `{"id": "...", "url": "...", "created_at": "..."}` with 201 status; Pro-only
- [ ] `DELETE /v1/webhooks/:id` — removes a webhook by ID; 404 if not found or not owned by the calling key; 204 on success; Pro-only
- [ ] Free or Developer key hitting `/v1/webhooks` returns RFC 7807 403 with `{"tier_required": "pro"}`
- [ ] Webhook delivery asynq task `TypeWebhookDeliver` registered in `internal/worker/tasks.go` (alongside existing Phase 1 tasks)
- [ ] Delivery payload: `{model_id, provider, old_price_input, old_price_output, new_price_input, new_price_output, confirmed_at, source}`
- [ ] Payload signed with HMAC-SHA256 using a per-webhook secret; signature sent in `X-LLMPricing-Signature: sha256=<hex>` header
- [ ] Delivery: at-least-once; 3 retries with exponential backoff (delays: 1m, 5m, 10m); asynq handles retry scheduling
- [ ] Non-2xx response from destination URL counts as failure → retry
- [ ] `webhooks` table migration created (if not already in Phase 1 migrations): `id`, `api_key_hash`, `url`, `secret`, `created_at`, `deleted_at`
- [ ] Webhook jobs enqueued by the reconciliation engine when a price change is confirmed (modify `internal/reconciler/reconciler.go` to enqueue — no direct writes, just enqueue)
- [ ] Unit tests for webhook handler (create, delete, ownership check) and delivery job (HMAC signing, retry behaviour)

## Technical Details
- New files: `internal/api/handlers/webhooks.go`, `internal/worker/webhook_handler.go`
- Modify: `internal/worker/tasks.go` (register TypeWebhookDeliver)
- Modify: `internal/reconciler/reconciler.go` (enqueue delivery job on confirmed change)
- Migration: `migrations/NNNN_create_webhooks.sql` if not already present
- Per-webhook secret: generated as 32-byte random hex on `POST /v1/webhooks`; stored hashed in DB; returned plaintext once at creation time (never again)
- RequireTier("pro") helper from Task 002 gates both routes
